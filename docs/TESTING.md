## Reproduce

```sh
python -m unittest discover -s tests -v
mkdir -p build
g++ -std=c++11 -Wall -Wextra -Werror tests/protocol_test.cpp -o build/protocol-test
build/protocol-test
python -m compileall -q monitor scripts tests
python scripts/check_source.py
python scripts/build_firmware.py
python -m tests.gui_smoke
python scripts/package.py
```

GUI smoke requires a Windows desktop or X display. Linux command in this
workspace used an isolated Xvfb display, not actual Windows hardware. Arduino
CLI1.3.1, Seeed nRF52 1.1.13, GCC9-2019q4, RadioLib7.3.0, Crypto0.4.0,
TinyGPSPlus1.0.3, adafruit-nrfutil0.5.3.post16; Python3.12, pyserial3.5.

MCU build reports upstream warnings in Crypto's unused RNG module and
TinyGPSPlus's fallthrough/custom-term copy. The deployment key is generated by
Python's OS CSPRNG, not Crypto RNG or Arduino `random`; Arduino `random` provides
collision jitter only. TinyGPSCustom is not used. GNSS parsing still needs HIL.
These warnings are retained, not disabled to force a green build.

## Revision 0.1.0-rc.2 verification additions

Source-level changes: default D0 button polarity matches the published Wio-SX1262
V1.0 schematic; gateway acknowledges each unique wearable status independently
instead of using a global 1.5 s timer. Native regression checks cover duplicate
STATUS and non-STATUS ACK suppression. These are design/code-review findings;
real button voltage, 100-trial multiwearable delivery and congested RF behavior
remain **BLOCKED** until measured in HIL. CI must rerun all gates on the final
commit; prior 0.1.0-rc.1 evidence is not transferable without verification.

## Release criteria

The workflow runs source checks, native/Python tests, all3 real MCU builds,
Windows tests, GUI smoke and executable packaging. Candidate publishing depends
on all jobs passing, permits only `-rc.` versions, and refuses to replace any
existing release. Hardware-blocked status is in the package manifest and notes.
Stable promotion requires every applicable criterion in SPEC.md and HIL.md on
final source/config, including measured link, watchdog and endurance results.

No known critical/high defect may ship at either tier. Missing hardware evidence
is not a passing test. A CI green build does not establish rescue readiness.
